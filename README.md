# Цифровая платформа ФСП Оренбургской области

Единая платформа регионального отделения Федерации спортивного программирования Оренбургской области. Здесь ведутся реестр спортсменов, тренеров, судей и организаций, календарь соревнований с заявками и протоколами, разряды и судейские категории со сроками, рейтинг и сборная региона, отчёты и документы. Платформа покрывает все шесть дисциплин вида спорта: алгоритмическое и продуктовое программирование, программирование систем информационной безопасности, систем искусственного интеллекта, робототехники и беспилотных авиационных систем.

> Все персональные данные в демонстрационной версии вымышлены.

## Быстрый старт

Нужны Docker Desktop и Node.js 20+.

```bash
cp .env.example .env
docker compose up -d --build
cd frontend && npm ci && npm run dev
```

| Что | Адрес |
| --- | --- |
| Платформа | http://localhost:5173 |
| API и документация OpenAPI | http://127.0.0.1:8002/docs |
| Почтовый ящик с письмами-уведомлениями (Mailpit) | http://localhost:8025 |

При старте backend сам применяет миграции и загружает демо-данные за 2024–2026 годы: 72 спортсмена всех шести дисциплин, 7 тренеров, 5 судей, 10 организаций, 60 проведённых соревнований с протоколами и судейскими коллегиями, присвоенные разряды и заявки на рассмотрении. Чистая база без демо-данных — `DEMO_DATA=0` в `.env`.

## Как устроено

- **Frontend:** React 19, TypeScript, Vite, React Router. Стиль — по мотивам fsp-russia.ru, адаптивная вёрстка.
- **Backend:** Python 3.12, FastAPI, Pydantic, SQLAlchemy 2 (async), Alembic.
- **Данные и документы:** PostgreSQL 17, python-docx (.docx), openpyxl (.xlsx).
- **Уведомления:** в кабинете и на email через SMTP (в Docker Compose — Mailpit), фоновая задача напоминаний.
- **Проверки:** тесты API на SQLite и PostgreSQL (миграции, `alembic check`, демо-данные), сборка фронтенда с проверкой типов; GitHub Actions.

Правила вида спорта, заложенные в платформу:
- возраст для допуска определяется по году рождения в календарном году соревнования;
- региональные соревнования включаются в календарный план Оренбургской области, межрегиональные и всероссийские — в ЕКП Минспорта России (проверяется на сервере);
- занимающийся учитывается в году, если начал занятия не позже и не прекратил их раньше этого года.

Ориентиры ЕВСК для подсветки кандидатов на разряд и сроки действия по умолчанию заполнены типовыми значениями — федерация сверяет их с действующими нормами и меняет через API и формы.

## Модель данных

- `users`, `roles`, `user_roles`, `auth_sessions` — аккаунт, назначенные роли, сессии с активной ролью; `users.pd_consent_at` — согласие на обработку ПД.
- `profiles` — общие данные человека (ФИО, дата рождения, пол, муниципалитет).
- `athlete_profiles` + `athlete_disciplines` — данные спортсмена, дисциплины, организация (NULL — «без организации»), законный представитель, РУСАДА.
- `coach_profiles` — данные тренера.
- Справочники: `disciplines`, `competition_types`, `age_groups`, `municipalities`, `organizations`, `judge_positions`.
- `competitions` + `competition_age_groups` — соревнование со ссылками на справочники, уровень, формат, календарный план и номер, файл положения, время публикации протокола.
- `applications` — заявка спортсмена: соревнование, возрастная группа, кто и из какой роли подал, статус (на модерации / одобрена / отклонена / отозвана), решение федерации. Одна заявка на спортсмена в соревновании.
- `results` — результат по одобренной заявке: баллы, итог (результат / не явился / дисквалифицирован), рассчитанное место.
- `coach_links` + `coach_link_events` — связь тренер — спортсмен по дисциплине со статусом и историей изменений.
- `judge_profiles`, `judge_category_requests`, `judge_assignments` — категория судьи со сроком и приказом, заявки на категорию, назначения в судейские коллегии с должностью.
- `rank_requests`, `athlete_ranks`, `rank_norms` — заявки на разряд с результатом-основанием, присвоенные разряды (дата, приказ, срок), ориентиры ЕВСК для подсветки кандидатов.
- `rating_points`, `rating_settings` — баллы рейтинга по уровню и типу соревнования, коэффициент стабильности.
- `sanctions` — дисквалификации и отстранения со сроками.
- `teams` + `team_members` — составы сборной с основным составом и резервом, снимок места и баллов рейтинга.
- `athlete_profiles.end_year` — год прекращения занятий для динамики численности.
- `certificates` — справки об участии: номер, случайный код для QR и проверки, результат-основание.
- `indicator_documents` — подтверждающие документы к показателям развития по годам.
- `audit_log` — журнал действий: время, автор, активная роль, действие, сущность, изменённые поля (было → стало).
- `notifications` — уведомления в кабинете, отметка о прочтении и отправке на email; `users.email_notifications` — настройка внешнего канала.

Правило календарных планов проверяется на сервере: региональные соревнования включаются в план Оренбургской области, межрегиональные и всероссийские — в ЕКП Минспорта России.
